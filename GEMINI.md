# Desearch

The `desearch` MCP server connects to the hosted Desearch endpoint `https://mcp.desearch.ai/mcp` and sends your Desearch API key in the `x-api-key` header. Get a key at https://console.desearch.ai/api-keys.

Version 0.10.0 exposes 51 tools:

- `ai-search`: AI search across web and X sources (also arxiv, wikipedia, hackernews, reddit) with relevant links and a summary. `youtube` is not a tool id.
- `web-search`: SERP-style web search. `search-api`: ranked pages, each with the passage that best matches the query. `web-links-search`: web link search.
- `x-search`: tweet search on X. `x-links-search`: AI search for X post links.
- `extract`: read a public URL as text or HTML. Prefer it over `web-crawl` (legacy route, same arguments).
- X data tools: `x-posts-by-urls`, `x-post-by-id`, `x-posts-by-user`, `x-post-retweeters`, `x-user-posts`, `x-user-replies`, `x-post-replies`, `x-trends`.
- `tiktok`, `facebook`, `instagram`: public posts, profiles, comments, and hashtags. Set `action` (for example `search`, `profile`, `profile_posts`, `comments`, `hashtag`) and that action's arguments. List actions return `next_cursor`: send it back unchanged as `cursor`, with the same action and target, for the next page. Facebook `search` and `hashtag` return Meta Ad Library ads. All three are read-only.
- `youtube`, `reddit`, `threads`: public YouTube videos, transcripts, comments, and channels; Reddit posts, subreddits, and comment trees; Threads posts, profiles, and user search. Same `action` pattern and `next_cursor` paging (`youtube` `search`, `comments`, `channel_videos` and `reddit` `search`, `subreddit_posts`, `comments` page; Threads returns one page). Each call is billed per request. All three are read-only.
- People Search: `people-search` starts a paid job billed to the user's Desearch balance (it reserves `count` people and bills only those it delivers). It is marked `readOnlyHint: false` and `destructiveHint: false`: it creates a new task and does not delete or overwrite anything. `openWorldHint` is true on every tool. Poll `people-search-status` with the `task_id` (searches usually take 1 to 5 minutes). Use `people-search-pause` and `people-search-resume` to pause and resume a search (`destructiveHint: false`, they undo each other) and `people-search-cancel` to stop it for good (`destructiveHint: true`, because cancel cannot be undone). `people-search-tasks` and `people-profiles` list past searches and the people they found, and `people-search-export` returns them as CSV or JSON Lines text. `people-search-status`, `people-search-tasks`, `people-profiles`, and `people-search-export` are read-only. All of these except `people-search` are free.
- Company Search: `company-search` finds companies on the web from a description and `company-enrich` reads the domains you send; each starts a paid job billed to the user's Desearch balance (it reserves `count` companies, or one per domain sent, and bills only those it delivers). Both are marked `readOnlyHint: false` and `destructiveHint: false`. Each company comes with its public emails, phones, and social profiles, and its leaders (CEO, founders, CTO, CFO by default) with LinkedIn profiles and emails; every contact keeps the page it came from. Poll `company-search-status` with the `task_id`: companies arrive with `enrichment` status `partial` and later stages fill them in, so read again without `cursor` for their latest version. `company-search-pause` and `company-search-resume` pause and resume a task (`destructiveHint: false`), `company-search-cancel` stops it for good (`destructiveHint: true`), and `company-search-tasks` lists past tasks. All of these except `company-search` and `company-enrich` are free.
- Monitors: `monitor-create` sets up a search over web, X, Reddit, YouTube, Threads, and TikTok (or watches up to 10 accounts per source with `x_accounts`, `reddit_subreddits`, `youtube_channels`, `tiktok_accounts`; `min_score: 0` keeps every new post; TikTok search has no date filter and ranks by relevance, so watch `tiktok_accounts` to follow creators) that reruns on a schedule (`interval` 1h to 7d) and keeps only new items that pass the screen (`relevant`, `new_info`, and one question per criterion; kept at `min_score`). Creating, reading, changing, and deleting monitors is free; each run is billed to the user's Desearch balance when it ends (its searches at list price, $0.05 per 1,000 items screened, and the summary's LLM usage plus 50%), and `run_now` (the default) queues the first run at once. `monitor-estimate` prices a configuration. `monitor-items`, `monitor-run`, and `monitor-runs` read what it found; `monitor-update` changes, pauses, or resumes it (`destructiveHint: true`: old settings are not kept); `monitor-trigger` runs it now (billed); `monitor-delete` removes it for good (`destructiveHint: true`). With `webhook_url`, kept items are POSTed to it, signed with the `webhook_secret` returned once by `monitor-create` and `monitor-webhook-rotate-secret` (`destructiveHint: true`); `monitor-webhook-test` sends a test event.

Use `web-search` or `ai-search` when the user asks for current information from the web, `x-search` for posts on X, `tiktok`, `facebook`, `instagram`, `youtube`, `reddit`, or `threads` for posts and profiles there (`youtube` `transcript` to read what a video says), and `extract` to read a specific page. Use `people-search` only when the user asks to find people, creators, or leads, because it is billed. Check `people-profiles` first when the user may already have searched for them. Use `company-search` only when the user asks to find companies or their contacts, and `company-enrich` when they give you domains, because both are billed. Use `monitor-create` only when the user asks to keep watching a topic over time, because every run is billed; use `monitor-estimate` first when they ask what it will cost.
